# C09 — Génération média sous réservation C05

**Qualification réelle : image NOT_RUN ; vidéo NOT_RUN.** Aucun identifiant ni budget de recette réelle explicitement autorisés. Aucun achat, déploiement ou appel de génération externe. Les adaptateurs HTTP sont réels ; les réponses utilisées pour les tests sont des fixtures, pas des reçus commerciaux.

## Parcours livré

Dans **Studio → Composition et versions**, enregistrer une révision, sélectionner une scène, ouvrir **Générer un média**. Le propriétaire confirme les droits et l’envoi du prompt (et de l’image de référence pour la vidéo). **Préparer sans facturer** fige les paramètres. Une seconde action autorise le plafond affiché en centimes USD. Le worker C05 peut alors soumettre. **Actualiser** lit uniquement la base, pas le fournisseur. La bibliothèque conserve la sortie vérifiée ; **Remplacer le visuel principal** crée une nouvelle révision de la scène source. Si la tête a changé, le placement automatique est refusé. Aucun ajout au calendrier ni publication.

Pour essayer le parcours complet avec autorisation ultérieure : partir d’une scène de vidéo courte de ≤ 5 s, générer et placer l’image, puis sélectionner cette image comme référence d’un clip. Approuver séparément le clip, le placer puis rendre la nouvelle version. L’image précédente reste un actif éditable et une révision restaurable. Le placement remplace l’image principale pleine largeur ou le clip, sans modifier les textes, logos ou autres scènes. Le master est remonté, les frames inchangées sont réutilisées.

## Architecture et exploitation

- Le conteneur historique câble `MockCapabilityProvider` au simulateur de routage, et `LocalProductionExecutor` vers Sharp/FFmpeg. Ils demeurent identifiés comme simulation et rendu local. Le parcours média C09 n’invoque pas ce mock, même sans clé. Il passe par le `MediaProvider` v1 (submit, poll, cancel, download), les capacités serveur v1 et la même bibliothèque/révision/rendu que l’éditeur C03/C08. La sélection du transport et les identifiants de modèle sont serveur, pas des options libres dans le Studio. Remplacer un modèle, une tarification ou un contrat incompatible nécessite une nouvelle version d’outil ; pas de bascule payante implicite.
- Appliquer la migration additive `20261120150000_media_generation` avant l’API et le worker. PostgreSQL, stockage partagé local ou S3, FFmpeg et FFprobe sont nécessaires. Variables : `MEDIA_GENERATION_ENABLED=0` par défaut ; `REPLICATE_API_TOKEN`, `RUNWAYML_API_SECRET` sont des **secrets worker**. L’API séparée utilise les indicateurs non secrets `MEDIA_IMAGE_CONFIGURED=1` / `MEDIA_VIDEO_CONFIGURED=1` (dérivés de la présence des clés dans le Compose). En environnement partagé, la présence des clés peut aussi être détectée côté serveur. Aucune variable `NEXT_PUBLIC_`. `FFMPEG_PATH`, `FFPROBE_PATH`, `DATABASE_URL`, `ARTIFACT_DIR` ou configuration S3 et variables Hatchet C05 restent nécessaires suivant le déploiement. `configured` signifie **configuré**, pas disponible, testé ou payé.
- Autoriser `media.image@1` / `media.video@1` explicitement sur le compte C05 et définir `limitCents` avec l’administration d’exécution existante. Un jeton seul ne suffit pas. La proposition et le snapshot sont atomiques. Le digest lie propriétaire via l’opération isolée, projet, révision, clé de requête, modèle, paramètres, SHA de la référence et plafond. L’application revalide avant envoi et n’exporte ni prompt ni jeton dans les logs de diagnostic. Le prompt et les identifiants externes restent dans le dossier du projet.
- La tâche Hatchet C05 revendique la réservation. **Un seul POST de génération** : `SUBMITTING` est persisté avant l’effet. Après enregistrement de l’identifiant distant, `POLLING` garde la réservation et réutilise le mécanisme C05 de notification pour de courtes lectures d’état (10 s). Pas de second orchestrateur. Un statut de surcharge transitoire lors d’une lecture reprogramme cette lecture ; jamais de répétition d’un POST ambigu. Après 30 min, expiration de claim, perte d’accusé ou incident financier : `UNKNOWN`, réservation conservée. Une annulation avant soumission libère la réservation ; après soumission, une demande worker au fournisseur, **aucune promesse de remboursement**. Si l’ID supprimé n’est plus consultable, le coût reste inconnu.
- Une sortie `READY` peut coexister avec une **facturation `UNKNOWN`** : conserver le résultat vérifié ne transforme pas un devis en coût rapporté. Un super-admin rapproche l’opération C05 avec un reçu vérifié et une référence de preuve via `/api/admin/execution/:id/resolve`. Ne jamais relancer une génération pour obtenir un reçu. Un coût au-delà du plafond déclenche l’incident C05, pas une imputation silencieuse. Un refus/échec avec un coût vérifié peut être réglé sans marquer le média `READY`.
- Les entrées sont des objets stricts ; prompt borné, révision et scène possédées, formats/durée fermés. Une référence est une version prête du même contexte, licence compatible, SHA vérifié, ≤ 3 Mio, dimensions bornées. URL de sortie acceptée uniquement par HTTPS sur les domaines de livraison approuvés (Replicate Delivery ou distribution Runway documentée), sans redirection ni jeton API. Si le CDN change, refuser et requalifier. Taille téléchargée limitée à 32 Mio. Décodage PNG / H.264 MP4, dimensions et durée vérifiées ; le flux vidéo est décodé jusqu’à la fin sous timeout. Le stockage applicatif vérifie son SHA avant publication dans la bibliothèque. Ni URL signée ni média brut dans la table de génération.

## Recette et limites

Commande sur une base PostgreSQL jetable locale suffixée `_test`, migrée, avec `DATABASE_URL_TEST`, `FFMPEG_PATH` et `FFPROBE_PATH` :

```sh
pnpm vitest run tests/media-providers.test.ts tests/v1/{media-generation,execution-broker,marketing-intelligence,creative-core}.test.ts
```

**25 tests réussis, 1 ignoré** (sidecar Hatchet réel). Les tests injectent un transport HTTP contrôlé dans les deux vrais adaptateurs. Ils exécutent le broker sur PostgreSQL, vérifient payloads, hôtes et absence de secret sur le CDN, refus sans budget, prompt altéré, timeout/perte d’accusé, déduplication, annulation distante, référence invalide, dimensions incorrectes et absence de re-soumission. Le parcours d’intégration produit une PNG fixture 1024², un clip H.264 fixture de 5 s, puis **trois vrais exports locaux** : composition initiale, image placée, clip placé. L’export final est relu et haché ; la frame de l’autre scène et le premier manifest sont préservés. Un adaptateur Prisma JS temporaire a été utilisé pour PostgreSQL de recette, non livré. Typecheck des workspaces, lint et build web réussis.

**NOT_RUN** : génération commerciale Replicate et Runway, facture réelle, exécution Hatchet distante, stockage S3 distant et déploiement. Les fixtures valident le protocole, les transactions et le rendu, pas la qualité visuelle ni la disponibilité des modèles.
